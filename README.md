# VPf10: AI-автоматизация отчетов

Обязательная часть домашнего задания: приложение принимает текст диалога с
клиентом, получает структурированный JSON напрямую через OpenAI API, заполняет
HTML-шаблон Jinja2 и сохраняет PDF через WeasyPrint в `reports/`.

Один тип отчета. Интерфейс консольный, изображения не обрабатываются.
Демонстрационные диалоги вымышлены. Приложение не подключено к реальному бизнесу.

## Что реализовано

1. Чтение UTF-8 / UTF-8 с BOM из файла или стандартного ввода; проверка пустого
   текста, кодировки и размера (до 40 000 символов).
2. Прямой запрос к `https://api.openai.com/v1` через OpenAI Python SDK,
   Responses API и Structured Outputs с Pydantic. Настройка `OPENAI_BASE_URL`
   из окружения не меняет адрес сервиса.
3. JSON с именем клиента, темой, запросом, оценкой тона, сроком, бюджетом,
   пожеланиями, следующими шагами и открытыми вопросами. Шаги имеют статус
   `agreed` / `proposed`; неизвестные значения представлены `null` или `[]`.
4. HTML-шаблон с автоэкранированием текста, кириллицей, форматом A4,
   нумерацией страниц и переносами на следующие страницы.
5. Сохранение PDF, JSON и HTML с уникальным именем. JSON содержит результат
   в поле `report`, а также время, SHA-256 входного текста, ID ответа, модель
   и фактическое использование токенов в служебных полях.
6. Обработка ошибок чтения, ключа, сети, таймаута, HTTP, лимита/баланса,
   отказа модели, неполного ответа, схемы JSON, шаблона и PDF.
7. Логирование этапов в терминал и `logs/app.log` с ротацией. Текст диалога,
   тело ответа API и ключ в журнал не записываются.

## Структура

```text
main.py                     # чтение, конфигурация, конвейер, сообщения об ошибках
run.sh                      # запуск в локальном окружении
utils/
  ai_processor.py           # прямой OpenAI Responses API
  schema.py                 # Pydantic-схема
  pdf_generator.py          # Jinja2 + WeasyPrint
  errors.py                 # безопасные сообщения об ошибках
templates/report_template.html
examples/dialog.txt         # полный учебный диалог
examples/minimal_dialog.txt # диалог без имени, бюджета и сроков
tests/test_pipeline.py
check_live.py               # платная интеграционная проверка двух диалогов
package_submission.py       # сборка ZIP исходников по явному списку
reports/                    # PDF, HTML и JSON
logs/                       # журнал этапов
requirements.txt
requirements-dev.txt
requirements-lock.txt       # версии проверенного окружения, включая зависимости тестов
.env.example                # пустой ключ
```

## Установка

Проверено на macOS, Python 3.13.13 и WeasyPrint 69.0. Системная библиотека Pango
на этом компьютере уже установлена через Homebrew; системные пакеты при
выполнении задания не устанавливались. На другом компьютере подготовьте Pango
по [официальной инструкции WeasyPrint](https://doc.courtbouillon.org/weasyprint/stable/first_steps.html).
На macOS код учитывает `/opt/homebrew/lib` и `/usr/local/lib`. Кэш Fontconfig
создается в `.cache/` проекта; при заданном `XDG_CACHE_HOME` используется он.

Клонируйте проект в путь **без двоеточия** и установите зависимости:

```bash
git clone https://github.com/vtaranov/zerocoder-vpf10-ai-automation.git
cd zerocoder-vpf10-ai-automation
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements-lock.txt
cp .env.example .env
```

Укажите в `.env` свой `OPENAI_API_KEY`; модель задается `OPENAI_MODEL`.
Значения переменных процесса имеют приоритет над `.env`. Запросы платные.
По умолчанию используется `gpt-6-luna`, также применявшаяся в VPf08.

Если исходный путь содержит `:`, Python отказывается создавать `venv` внутри
проекта. Переместите клон в путь без двоеточия или создайте выделенное окружение
`.venvs/vpf10-ai-automation` в родительской папке с подходящим путем.
`bash run.sh` ищет сначала `.venv` проекта, затем такое окружение в родительских
папках. Окружение и ключи в репозиторий не входят.

## Запуск

Из папки проекта:

```bash
bash run.sh examples/dialog.txt
```

Если установлена собственная `.venv`:

```bash
.venv/bin/python main.py examples/dialog.txt
.venv/bin/python main.py - < examples/dialog.txt
.venv/bin/python main.py examples/dialog.txt --output-dir reports
```

По умолчанию результаты сохраняются в `reports/` **от корня проекта**;
относительные входные пути и `--output-dir` CLI отсчитываются от текущей папки.
`run.sh` перед запуском переходит в папку проекта.

После успеха появятся три файла с общим именем:

```text
reports/report_YYYYMMDD_HHMMSS_XXXXXXXX.json
reports/report_YYYYMMDD_HHMMSS_XXXXXXXX.html
reports/report_YYYYMMDD_HHMMSS_XXXXXXXX.pdf
```

Время отчета: Europe/Moscow. Успех возвращает код 0, обработанная ошибка - 1,
ошибка аргументов - 2, отмена Ctrl+C - 130. SDK ограничен таймаутом 60 секунд
на попытку и двумя повторами для временных ошибок. При ошибке PDF уже полученные
JSON и HTML сохраняются для диагностики; частичный PDF удаляется.

## Проверки

Для окружения `.venv`:

```bash
.venv/bin/python -m unittest discover -s tests -v
# Два настоящих платных запроса, только вымышленные примеры:
.venv/bin/python check_live.py
```

При использовании окружения в родительской папке укажите путь к его Python
вместо `.venv/bin/python`.

Локальные тесты проверяют входные данные, схему, адрес API, отсутствие секретов
в сообщениях ошибок, отказ и неполный ответ, экранирование HTML, создание PDF
через настоящий WeasyPrint, кириллицу, многостраничность, уникальные имена
и поведение при ошибке PDF. API в модульных тестах заменен mock-объектом;
интеграционный `check_live.py` использует реальный API и сохраняет протокол
в `local_checks/live_check.json`.

## Данные и ограничения

Текст диалога отправляется в OpenAI для обработки. `store=False` отключает
сохранение Response для последующего получения через API, но не означает
полного отсутствия хранения на стороне провайдера. JSON, HTML и PDF содержат
сведения из диалога и сохраняются локально. Извлечение фактов остается
вероятностным: проверка схемы подтверждает структуру, а не фактическую точность.
Перед использованием отчета проверьте смысл, суммы, сроки и договоренности.

`.env`, кэш, отчеты, журналы и протоколы исключены через `.gitignore`.
В репозиторий включены исходники, тесты, вымышленные примеры и пустой
`.env.example`; реальный ключ, окружение, журналы и результаты рабочих запусков
остаются локально. Для сдачи используется ссылка на репозиторий.

При необходимости `package_submission.py` позволяет отдельно собрать ZIP
исходников по явному списку, с проверкой целостности и поиском строки API-ключа.
