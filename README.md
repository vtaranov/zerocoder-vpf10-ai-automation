# VPf10 — генератор PDF-отчетов из диалогов

Консольное приложение превращает текст разговора с клиентом в структурированный
отчет. Оно отправляет диалог напрямую в OpenAI API, получает JSON, заполняет
HTML-шаблон Jinja2 и создает PDF через WeasyPrint. JSON и HTML сохраняются рядом
с PDF для проверки результата.

Отчет включает имя клиента, тему, основной запрос, оценку тона, пожелания,
бюджет, сроки, следующие шаги и открытые вопросы. Предложенные действия
отмечаются отдельно от согласованных. В репозитории есть вымышленные диалоги
для первого запуска. Приложение работает с готовым текстом; аудио и изображения
не обрабатываются.

## Готовые примеры отчетов

Результат можно посмотреть без установки приложения и запросов к API:

| Исходный диалог | Готовый PDF |
| --- | --- |
| [Полный диалог](examples/dialog.txt) | [Отчет, 2 страницы](examples/reports/dialog.pdf) |
| [Короткий диалог без имени, бюджета и сроков](examples/minimal_dialog.txt) | [Отчет, 1 страница](examples/reports/minimal_dialog.pdf) |

PDF сформированы через WeasyPrint по ответам `gpt-6-luna`. Все сведения
в диалогах вымышлены. При повторной генерации формулировки могут отличаться.

## Требования

- Python 3.11 или новее для зафиксированных зависимостей. Проверенная версия — Python 3.13.13.
- Git для клонирования репозитория.
- Системная библиотека Pango и шрифт с поддержкой кириллицы.
- Доступ к интернету и собственный ключ OpenAI API с доступом к выбранной модели
  и средствами для оплаты запросов. По умолчанию используется `gpt-6-luna`.

Команды ниже предназначены для macOS и Linux и выполняются в терминале.
Для других операционных систем сначала подготовьте системные зависимости по
[инструкции WeasyPrint](https://doc.courtbouillon.org/weasyprint/stable/first_steps.html).

## Установка

### 1. Установите системные зависимости

**macOS:** установите [Homebrew](https://brew.sh/), если он еще не установлен,
затем выполните:

```bash
brew install python@3.13 git pango
```

**Ubuntu 24.04+ / Debian 12+:**

```bash
sudo apt update
sudo apt install -y git python3 python3-venv python3-pip \
  libpango-1.0-0 libpangoft2-1.0-0 libharfbuzz-subset0 fonts-dejavu-core
```

Проверьте версию Python:

```bash
python3 --version
```

Если она ниже 3.11, установите более новую версию Python. Если Python 3.13
доступен под командой `python3.13`, используйте ее вместо `python3` при создании
окружения на следующем шаге.

### 2. Клонируйте репозиторий

```bash
git clone https://github.com/vtaranov/zerocoder-vpf10-ai-automation.git
cd zerocoder-vpf10-ai-automation
```

Остальные команды выполняйте из этой папки. На macOS и Linux выбирайте путь
без символа `:`: он мешает Python создавать виртуальное окружение.

### 3. Создайте окружение и установите Python-библиотеки

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements-lock.txt
```

`requirements-lock.txt` фиксирует версии зависимостей, включая библиотеки для
тестов. Команды используют Python из `.venv`, поэтому активировать окружение
отдельно не требуется.

### 4. Настройте ключ API

```bash
cp .env.example .env
```

Откройте `.env` в текстовом редакторе и укажите свой ключ:

```dotenv
OPENAI_API_KEY=your_openai_api_key
OPENAI_MODEL=gpt-6-luna
```

Замените `your_openai_api_key` действительным ключом из
[OpenAI Platform](https://platform.openai.com/api-keys). При необходимости
измените модель на доступную вашему проекту модель с поддержкой Responses API
и Structured Outputs.

Файл `.env` исключен из Git. Не публикуйте ключ и не добавляйте его в исходники.
Если `OPENAI_API_KEY` или `OPENAI_MODEL` уже заданы в переменных терминала,
они имеют приоритет над `.env`.

## Первый запуск

Создайте отчет по демонстрационному диалогу:

```bash
.venv/bin/python main.py examples/dialog.txt
```

Команда выполнит платный запрос к OpenAI. В терминале появятся сообщения
об этапах обработки и строка `Отчет успешно создан:` с путем к PDF.
Откройте этот файл в браузере или программе для просмотра PDF.

Результаты сохраняются в папке `reports/` проекта с общим именем:

```text
reports/report_YYYYMMDD_HHMMSS_XXXXXXXX.pdf
reports/report_YYYYMMDD_HHMMSS_XXXXXXXX.json
reports/report_YYYYMMDD_HHMMSS_XXXXXXXX.html
```

PDF — готовый отчет. HTML — заполненный шаблон. JSON содержит данные отчета
в поле `report`, а также время создания, SHA-256 входного текста, модель,
ID ответа API и фактическое использование токенов. Время отчета указано
в часовом поясе Europe/Moscow.

## Обработка своего диалога

Сохраните текст разговора в UTF-8 файле, например `dialog.txt`. Допускается
UTF-8 с BOM. Файл должен содержать непустой текст длиной до 40 000 символов.

```bash
.venv/bin/python main.py dialog.txt
```

Для чтения из стандартного ввода:

```bash
.venv/bin/python main.py - < dialog.txt
```

Для сохранения результатов в другую папку:

```bash
.venv/bin/python main.py dialog.txt --output-dir output
```

Относительные входные пути и значение `--output-dir` отсчитываются от текущей
папки терминала. Папка результатов создается автоматически. Без `--output-dir`
используется `reports/` в корне проекта.

Справка по аргументам:

```bash
.venv/bin/python main.py --help
```

## Если возникла ошибка

Основные этапы и ошибки выводятся в терминал и записываются в `logs/app.log`.
Журнал ротируется; текст диалога, тело ответа API и ключ в него не записываются.

| Сообщение или ситуация | Что проверить |
| --- | --- |
| Не задан `OPENAI_API_KEY` | Создайте `.env` в корне проекта и заполните ключ. |
| OpenAI отклонил ключ | Проверьте ключ и переменные терминала: они могут переопределять `.env`. |
| Лимит запросов или недостаточно средств | Проверьте лимиты и баланс проекта OpenAI; повторите запрос позже. |
| Нет доступа к модели / HTTP-ошибка | Проверьте `OPENAI_MODEL` и доступность этой модели вашему API-проекту. |
| Не удалось подключиться / таймаут | Проверьте интернет и доступ к `api.openai.com`. |
| Не удалось прочитать диалог | Проверьте путь, права доступа и кодировку UTF-8. |
| WeasyPrint не смог создать PDF | Проверьте установку Pango и Python-зависимостей в `.venv`. |
| Вместо кириллицы видны квадраты | Установите шрифт с кириллицей; в Ubuntu / Debian подойдет `fonts-dejavu-core`. |

На macOS приложение ищет библиотеки Homebrew в `/opt/homebrew/lib` и
`/usr/local/lib`. При установке Pango в другое место укажите путь к библиотекам
через `DYLD_FALLBACK_LIBRARY_PATH`, как описано в
[разделе WeasyPrint о загрузке библиотек](https://doc.courtbouillon.org/weasyprint/stable/first_steps.html#missing-library).

Если ошибка возникла на этапе PDF, уже полученные JSON и HTML останутся в папке
результатов. Частичный PDF удаляется. SDK использует таймаут 60 секунд на попытку
и до двух повторов для временных ошибок. Код завершения: `0` — успех, `1` —
обработанная ошибка, `2` — неверные аргументы, `130` — отмена через Ctrl+C.

## Проверка установки и тесты

Проверьте совместимость установленных Python-зависимостей и запустите тесты:

```bash
.venv/bin/python -m pip check
.venv/bin/python -m unittest discover -s tests -v
```

Тесты работают без ключа и не обращаются к OpenAI. Они проверяют чтение текста,
схему JSON, обработку ошибок, экранирование HTML, настоящую генерацию PDF,
кириллицу, многостраничность и сохранение файлов при сбоях.

Для отдельной проверки с реальным API и двумя вымышленными диалогами:

```bash
.venv/bin/python check_live.py
```

Эта проверка выполняет **два платных запроса**, создает отчеты в `reports/`
и сохраняет протоколы в `local_checks/`. Перед запуском настройте `.env`.

## Структура проекта

```text
main.py                     # консольный интерфейс и последовательность обработки
utils/ai_processor.py       # прямой OpenAI Responses API
utils/schema.py             # Pydantic-схема отчета
utils/pdf_generator.py      # заполнение HTML и генерация PDF
utils/errors.py             # сообщения об ошибках
templates/report_template.html
examples/                   # вымышленные диалоги для проверки
examples/reports/           # готовые PDF по этим диалогам
tests/                      # автоматические тесты без запросов к OpenAI
check_live.py               # проверка с реальным API
reports/                    # созданные PDF, JSON и HTML
logs/                       # журнал приложения
requirements-lock.txt       # зафиксированные версии зависимостей
.env.example                # образец настроек без ключа
```

## Данные и ограничения

Текст диалога отправляется в OpenAI. Приложение использует прямой адрес
`https://api.openai.com/v1`; переменная `OPENAI_BASE_URL` этот адрес не меняет.
`store=False` отключает сохранение Response для последующего получения через
API, но не означает полного отсутствия хранения данных у провайдера.

JSON, HTML и PDF сохраняются на диске и содержат сведения из диалога. Эти файлы,
создаваемые в `reports/`, а также `.env`, журналы, кэш и протоколы тестирования
исключены через `.gitignore`. Готовые PDF вымышленных примеров из
`examples/reports/` включены в репозиторий.

Извлечение фактов вероятностное: проверка схемы JSON подтверждает структуру,
но не точность содержания. Перед использованием отчета проверьте суммы, сроки,
имена и договоренности. Оценка тона разговора также приблизительна.
